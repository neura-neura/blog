# Blog Studio
Reproduce the supplied X Articles editor: white canvas, black ink, native system stack (-apple-system, BlinkMacSystemFont, Segoe UI, Roboto, Helvetica, Arial, sans-serif), thin #eff3f4 separators, gray #536471 secondary text, blue #1d9bf0 actions. Center the workspace in a 1056px shell: 88px icon rail, 286px article list, and flexible document (682px at full width). Below 1100px hide the article list and center a 768px shell. Below 641px retain a 68px vertical rail and let the document fill the remaining width; keep formatting controls horizontally scrollable inside their toolbar. The rail and editor toolbar remain sticky. Use 48px article padding on desktop and 24px on mobile. Cover 5:2, with at least 118px height on mobile. Measured from X Articles: title 34px/44px weight 800 with normal letter-spacing at both desktop and mobile widths; article body 17px/28px weight 400. Interface: preview 15px/20px bold, publish 14px/16px bold, formatting labels 14px/16px, author name 15px/20px bold and handle 15px/20px regular. Use the same native font stack in the editor, published articles and HTML exports; no downloaded webfont is needed. Font choice follows the OS, like X (Segoe UI was verified as the rendered Windows font). Preserve all visible editor controls, native accessible dialogs, keyboard editing, focus and preview modes. Focus mode hides both navigation columns and centers an 800px document. Blog actions replace social navigation. No X branding.

Appearance is a local browser preference shared by the editor and generated reading pages. Settings > Apariencia offers X's measured #1d9bf0, #ffd400, #f91880, #7856ff, #ff7a00, #00ba7c plus each mixed with 60% white for pastel variants. Five font settings (13,14,15,17,18 UI px) scale title and body proportionally from the measured default. Backgrounds are default white and lights-out black, with an optional live system preference. Preserve original X accent fills and link colors, with white primary-button labels and selected checkmarks for all six original colors. Pastel additions also use white button labels and checkmarks, as explicitly requested by the user; their link colors remain adapted for legibility. Hover darkens the button background only, preserving the label color. Store validated options under blog-studio-appearance-v1, independently of articles and GitHub credentials.

Publication feedback uses neutral ink, muted supporting copy, a status icon and a pill-shaped primary action. Do not expose the article link after the GitHub commit alone: wait for the actual HTML to respond successfully with the matching article-version timestamp. Probe with cache-busting URLs so CDN 404s and older updates do not count as ready. A custom static 404 page waits for newly deployed article URLs and opens them automatically. Failure and timeout states allow checking again without another publication.
Cover images use a 5:2 crop in both the editor and generated articles. Before saving, show the original in a square crop stage with faded regions outside the fixed frame, an accent outline, drag positioning, keyboard arrows and a zoom slider. Apply produces a real 5:2 WebP; cancel preserves the existing cover. Keep the original source and crop settings locally for later adjustments. Existing portrait covers receive a centered 5:2 object-fit crop when pages rebuild.

The public home uses X-inspired profile and feed components: a 600px center column with thin separators, a cover banner, overlapping circular initial avatar, author bio, publication count, a search pill and bordered article cards with 5:2 covers, excerpts and reading times. Desktop adds a left navigation rail and right information cards; tablet collapses the rail to icons and hides the right column, while phones use a full-width feed with a compose action in the sticky header. Search filters titles, excerpts and tags without navigating away; topic buttons apply the same filter. Preserve shared accent and background preferences. Reading pages have distinct back-to-articles and write actions. A white feather on a dark rounded square is the favicon for the editor, home, articles and waiting/404 page.

Identity is one global public profile (author, public handle and bio), independent of GitHub connection credentials and article content. Settings update every author label, initial avatar, handle and bio immediately, including open home and article tabs. Persist edits by site path; unsent edits survive reload and must not be replaced by older CDN responses. Saving with a token publishes only the public profile to blog-profile.json; the static build applies it to all old and new articles, home, public JSON and RSS. Existing settings migrate without deleting drafts. A token status card at the top of Settings and a small accent dot on its navigation icon indicate whether this browser has a saved token. Describe stored presence separately from validity, which GitHub confirms on authenticated operations. Tokens persist locally by site path in localStorage, shared across tabs and browser restarts. Disconnect clears all open tabs and prevents older session values from restoring a removed token. Migrate existing sessionStorage credentials once; never include credentials in public profile files.

The public blog is a reading experience: home, search, articles, author information and RSS only. Never render editor or compose links in the home or generated articles. The author opens editor.html directly; its entry screen verifies the stored GitHub token and repository push permission before importing or mounting the editing interface. Visitors without authorized credentials see an access form and a return-to-articles link, with no publishing, settings or draft controls. Invalid tokens are not persisted by this login form. Disconnect returns every open editor tab to the access screen. GitHub enforces authorization for all actual repository writes; no server is required for this static site.

The blog profile banner is an explicit public profile setting, entirely independent of article covers. Never infer it from a post. An unset or removed banner renders a neutral surface. Settings provide upload/change, preview, adjust and remove controls, with a 3:1 crop and zoom before applying; cancel preserves the previous image and other form values. Save publishes only the cropped banner with the public profile and updates open home tabs. Article cover cropping remains 5:2. Persist safe raster data URLs or HTTPS images; reject SVG and executable URLs.

More options includes an explicit “Guardar borrador privado” action, separate from automatic local saving and public publication. Copies live only in a separate private `<repo>-drafts` repository, verified as private before every read and write. The single “Borradores” list merges local drafts and private snapshots by ID, with storage labels for local-only, private-only, matching copies and local changes after a private save. There is no separate private tab or private list. Mobile users reach the same unified list from the articles dialog. Use existing neutral dialogs, accent pill actions and muted explanatory text. A failed permission check offers retry and clear token repository-selection instructions. Preserve differing local content as a separate draft before restoring a private snapshot; reject stale remote writes rather than overwriting another device's work. Never include private snapshots in the public build or publish private save metadata with articles.
